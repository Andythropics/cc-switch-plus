# 3.3 Skills 管理

## 対応プラットフォーム

再設計された Skills システムは **macOS** のみで利用できます。Windows と Linux では既存の Skill ファイルとデータベース状態を変更せず、部分的な管理機能の代わりにプラットフォーム案内を表示します。

## Library と Consumer

CC Switch は 1 つの非公開 **Library** ですべての Skill を管理します。Library の項目が唯一の管理対象ソースです。Claude と Codex は **Consumer** であり、Skill を有効にすると公式 Consumer ディレクトリから Library への管理リンクを作成します。Skill のコピーは作成しません。

管理リンク経由の編集は Library の内容を更新します。Consumer ディレクトリ内の実ディレクトリ、外部リンク、壊れたリンク、変更された管理リンクは競合またはドリフトとして表示され、暗黙には上書きされません。

Skills には次のビューがあります。

- **Library**：Library 項目の取得、確認、更新、削除。
- **Global**：ユーザー単位の Claude/Codex デプロイ。
- **Projects**：プロジェクトワークスペースの登録とプロジェクト単位のデプロイ。
- **Activity**：Skill 操作の構造化された結果。
- **Discovery**：設定済みリポジトリまたは skills.sh からの検索。

## Skill を Library に追加する

Discovery、リポジトリ、ローカル ZIP から Skill を取得できます。取得時に Skill を検証し、Claude/Codex 互換性を確認して、非公開 Library に 1 つのスナップショットを保存します。取得だけでは Skill は有効になりません。

リポジトリ由来の Library 項目は更新を確認できます。スナップショットを置き換える前に、ローカル変更、Consumer 互換性、影響を受けるデプロイを検証します。破壊的な操作では管理バックアップを作成し、補償が必要な場合は復旧情報を表示します。

## Skill をデプロイする

1 つ以上の Library 項目を選び、Claude、Codex、または両方を選択します。

- **Global** は公式ユーザーディレクトリを使用します。
- **Project** は登録済みプロジェクトワークスペースを使用します。
- バッチ操作は要求順を保ち、各項目の結果を個別に表示します。

CC Switch は次の公式ディレクトリを使用します。

| スコープ | Claude                      | Codex                       |
| -------- | --------------------------- | --------------------------- |
| Global   | `~/.claude/skills/`         | `~/.agents/skills/`         |
| Project  | `<project>/.claude/skills/` | `<project>/.agents/skills/` |

`~/.codex/skills/` は移行時に確認する旧ディレクトリであり、新しい Codex デプロイ先ではありません。

デプロイ状態では、同期済み、リンク欠落、ドリフト、競合、ブロック中のワークスペース、利用不能なワークスペースを区別します。観測状態を確認してから、表示された **Repair**、**Forget**、復旧操作を使用してください。CC Switch は同じファイル名だけで所有権を判断しません。

## Project Workspaces

Skill Deployment を管理する前に Project Workspace を登録します。Active な Project Workspace にはデプロイできます。Archived または Unavailable の Project Workspace は確認できますが、変更はブロックされます。Unmanaged Skill import では、コンテンツを Library に追加するか、競合と Git exclude の確認後に管理対象の Skill Deployment へ置き換えられます。

## ガイド付き移行

macOS でアップグレード後に初めて Skills を開くと、読み取り専用の事前確認を行います。旧 DB 行、管理対象と非管理対象の内容、旧 Codex リンク、ターゲット競合、バックアップ前提条件を一覧表示します。

- **Defer**：このセッションでは延期し、旧 DB とファイルシステムを変更しません。
- **Apply**：確認した観測トークンを受け入れ、検証済み DB/コンテンツバックアップを作成し、各手順を記録します。
- **Resume**：完了済みの処理を繰り返さず、永続化された進捗から続行します。
- **Restore**：検証済み移行バックアップを使い、新しい外部コンテンツがある場所は上書きしません。

非管理コンテンツと曖昧なリンクは手動解決のため保持されます。すべての管理対象処理が完了するまで、旧状態は消去されません。

## 同期とデバイス固有状態

Library の内容と可搬な Library メタデータは同期できます。プロジェクトパス、期待デプロイ、Activity 履歴、復旧候補、移行ジャーナルなど、端末固有の観測状態は現在の端末だけに保持されます。

別の Mac に Library を同期した後は、その端末で必要な Skill を確認してデプロイしてください。他端末のワークスペースパスやデプロイリンクは再生されません。

Profiles は Skills を保存または適用しません。状態と競合を明示的に確認できる Skills ビューからデプロイを管理してください。
