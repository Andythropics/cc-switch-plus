# 3.3 Skills

## Platform Support

The redesigned Skills system is available on **macOS**. Windows and Linux keep their existing Skill files and database state unchanged; the app shows a platform notice instead of exposing a partial management experience.

## Library and Consumers

CC Switch manages every Skill from one private **Library**. A Library item is the only managed source copy. Claude and Codex are **Consumers**: enabling a Skill creates a managed link from an official consumer directory to the Library instead of copying the Skill.

Edits made through a managed consumer link update the Library copy. A real folder, foreign link, broken link, or changed managed link in a consumer directory is reported as a conflict or drift and is never silently overwritten.

The Skills area has these views:

- **Library**: acquire, inspect, update, and remove Library items.
- **Global**: manage Claude and Codex deployments for your user account.
- **Projects**: register project workspaces and manage project-scoped deployments.
- **Activity**: review structured outcomes for Skill operations.
- **Discovery**: find Skills from configured repositories or skills.sh.

## Add Skills to the Library

You can acquire a Skill from Discovery, a repository source, or a local ZIP file. Acquisition validates the Skill, checks Claude and Codex compatibility, and stores one snapshot in the private Library. It does not enable the Skill automatically.

Repository-backed Library items can be checked for updates. Before replacing a snapshot, CC Switch verifies local modifications, Consumer compatibility, and affected deployments. Destructive operations create a managed backup and report recovery details when compensation is required.

## Deploy Skills

Choose one or more Library items, then choose Claude, Codex, or both.

- **Global** deployments use the official user directories.
- **Project** deployments use a registered project workspace.
- Batch operations preserve request order and show an outcome for every item.

CC Switch uses these official directories:

| Scope   | Claude                      | Codex                       |
| ------- | --------------------------- | --------------------------- |
| Global  | `~/.claude/skills/`         | `~/.agents/skills/`         |
| Project | `<project>/.claude/skills/` | `<project>/.agents/skills/` |

`~/.codex/skills/` is treated as a legacy location during migration, not as the redesigned Codex deployment target.

Deployment status distinguishes in-sync links, missing links, drift, conflicts, blocked workspaces, and unavailable workspaces. Use the offered **Repair**, **Forget**, or recovery action only after reviewing the observed state. CC Switch never derives ownership from a matching file name alone.

## Project Workspaces

Register a Project Workspace before managing Skill Deployments there. Active Project Workspaces can receive deployments; archived or unavailable Project Workspaces remain visible but block mutation. Unmanaged Skill import can admit content into the Library or replace it with a managed Skill Deployment after conflict and Git-exclude checks.

## Guided Migration

On the first Skills visit after upgrading on macOS, CC Switch performs a read-only preflight. It inventories legacy rows, managed and unmanaged content, old Codex links, target conflicts, and backup prerequisites.

- **Defer** leaves legacy database and filesystem state unchanged for the current session.
- **Apply** accepts the exact reviewed observation token, creates verified database and content backups, and journals every step.
- **Resume** continues a durable interrupted run without repeating completed work.
- **Restore** uses the verified migration backup and refuses to overwrite changed foreign content.

Unmanaged content and ambiguous links are preserved for manual resolution. The migration does not clear legacy state until all managed work is complete.

## Sync and Device-Local State

Library content and portable Library metadata can be synchronized. Machine-specific observations stay on the current device, including project workspace paths, desired deployments, activity history, recovery proposals, and migration journals.

After syncing the Library to another Mac, inspect and deploy the required Skills on that device. Sync does not replay another machine's workspace paths or deployment links.

Profiles do not capture or apply Skills. Manage Skill deployments from the Skills views so their status and conflicts remain explicit.
