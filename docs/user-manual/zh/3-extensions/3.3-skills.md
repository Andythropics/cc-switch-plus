# 3.3 Skills 技能管理

## 平台支持

重新设计的 Skills 系统仅在 **macOS** 上提供。Windows 和 Linux 会保持现有 Skill 文件与数据库状态不变；应用只显示平台说明，不会开放不完整的管理功能。

## Library 与 Consumer

CC Switch 通过一个私有 **Library** 管理所有 Skill。Library 中的条目是唯一的受管源副本。Claude 和 Codex 是 **Consumer**：启用 Skill 时，CC Switch 会从官方 Consumer 目录创建指向 Library 的受管链接，而不是复制文件。

通过受管链接编辑 Skill，会直接更新 Library 副本。Consumer 目录中的真实文件夹、外来链接、断链或被修改的受管链接都会显示为冲突或漂移，CC Switch 不会静默覆盖。

Skills 区域包含以下视图：

- **Library**：获取、检查、更新和删除 Library 条目。
- **Global**：管理当前用户的 Claude 与 Codex 部署。
- **Projects**：注册项目工作区并管理项目级部署。
- **Activity**：查看 Skill 操作的结构化结果。
- **Discovery**：从已配置仓库或 skills.sh 发现 Skill。

## 将 Skill 加入 Library

可以从 Discovery、仓库来源或本地 ZIP 获取 Skill。获取流程会验证 Skill、检查 Claude/Codex 兼容性，并在私有 Library 中保存一份快照；获取不会自动启用 Skill。

仓库来源的 Library 条目可以检查更新。替换快照前，CC Switch 会检查本地修改、Consumer 兼容性和受影响的部署。破坏性操作会创建受管备份；补偿失败时会显示恢复信息。

## 部署 Skill

选择一个或多个 Library 条目，再选择 Claude、Codex 或两者。

- **Global** 部署使用官方用户目录。
- **Project** 部署使用已注册的项目工作区。
- 批量操作按请求顺序执行，并为每个条目显示独立结果。

CC Switch 使用以下官方目录：

| 范围    | Claude                      | Codex                       |
| ------- | --------------------------- | --------------------------- |
| Global  | `~/.claude/skills/`         | `~/.agents/skills/`         |
| Project | `<project>/.claude/skills/` | `<project>/.agents/skills/` |

`~/.codex/skills/` 仅作为迁移期间检查的旧位置，不是新系统的 Codex 部署目标。

部署状态会区分已同步、链接缺失、漂移、冲突、工作区已阻止和工作区不可用。只有在确认观察结果后，才使用界面提供的 **Repair**、**Forget** 或恢复操作。CC Switch 不会仅凭同名文件判断所有权。

## 导入未托管的全局 Skill

Global 视图会持续以只读方式扫描 `~/.claude/skills/` 与 `~/.agents/skills/` 下的真实一级 Skill 目录。隐藏项、符号链接、嵌套目录以及没有规范 `SKILL.md` 的目录不会成为导入候选。该流程独立于一次性的引导迁移，也绝不会自动接管外部内容。

- **仅导入 Library 副本**：验证 Skill 并复制到 Library，外部目录保持不变。
- **导入并交由管理**：需要明确确认并通过对应 Consumer 的兼容性检查。CC Switch 会备份外部目录、导入 Library，再用指向 Library 的绝对受管链接替换原目录。之后再次运行原始安装器（例如 `npx`）可能覆盖该部署或与其冲突。

每次应用都会重新核对扫描令牌与内容哈希；任一发生变化时，需要刷新 Global 视图后再试。

## Project Workspace

管理 Skill Deployment 前需要先注册 Project Workspace。活动的 Project Workspace 可以接收部署；已归档或不可用的 Project Workspace 仍会显示，但禁止修改。Unmanaged Skill import 可以把内容加入 Library，或在冲突与 Git exclude 检查通过后，用受管 Skill Deployment 替换项目副本。

## 引导式迁移

在 macOS 升级后首次进入 Skills 时，CC Switch 会执行只读预检，列出旧数据库记录、受管与非受管内容、旧 Codex 链接、目标冲突以及备份前置条件。

- **Defer**：本次会话暂缓，旧数据库和文件系统保持不变；正常 Skills 视图仍可只读浏览，并提供继续审查入口。
- **Apply**：接受刚刚审查的观察令牌，创建经过验证的数据库与内容备份，并记录每一步。
- **Resume**：从持久化进度继续，不重复已经完成的步骤。
- **Restore**：使用经过验证的迁移备份；如果现场出现新的外来内容，则拒绝覆盖。

迁移计划会明确区分自动执行、原样保留、经用户确认后保留的不支持 Consumer 内容，以及 Apply 前必须解决的真实冲突。不支持 Consumer 的保留内容不是失败的 Deployment，也不会进入 Repair 流程。

Apply 后，所有 Skills 视图仍可打开持久化迁移报告，查看已执行与已保留项目。只有本次 run 的迁移备份仍通过验证时才显示 Restore。确认已知晓只会隐藏提醒，不会删除历史报告。所有受管任务完成前，迁移不会清除旧状态。

## 同步与设备本地状态

Library 内容和可移植的 Library 元数据可以同步。与机器有关的观察状态只保留在当前设备，包括项目工作区路径、期望部署、Activity 历史、恢复建议和迁移日志。

将 Library 同步到另一台 Mac 后，需要在那台设备上重新检查并部署所需 Skill。同步不会重放其他设备的工作区路径或部署链接。

Profiles 不再保存或应用 Skills。请在 Skills 视图中管理部署，以便明确查看状态与冲突。
